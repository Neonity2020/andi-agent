# 第三阶段：运行时审批、事件与会话

## 1. 目标

让 Agent 可以安全地处理白名单之外但用户明确同意的命令，同时提供可观察的执行过程和可恢复的多轮会话。

完成后应具备：

- 安全命令继续自动放行；
- 其他命令在终端显示完整参数并逐条询问；
- 非交互环境默认拒绝需要审批的命令；
- CLI 实时输出模型轮次、工具开始、工具结果和上下文裁剪事件；
- 使用 `--session ID` 保存并恢复消息历史；
- 历史超过预算时按完整用户轮次裁剪，避免孤立的工具消息。

## 2. 命令审批

### 2.1 两级策略

1. **自动允许**：第二阶段已有的测试、检查、构建和只读 Git 命令。
2. **用户审批**：其他 `program + args[]` 命令只有在 `--approval ask`、终端可交互且用户输入 `y` 时才执行。

命令仍直接传给 `Bun.spawn`，不自动拼接 shell 字符串。审批界面会显示 JSON 序列化后的完整参数，避免空格或特殊字符造成歧义。

模式：

- `--approval ask`（默认）：需要时询问；stdin 不是 TTY 时拒绝。
- `--approval never`：只执行自动允许命令，从不询问。

拒绝是正常工具结果，模型可以选择其他方案，不能绕过审批。

## 3. Agent 事件流

核心循环提供结构化回调，不直接依赖终端：

- `turn_started`
- `model_completed`
- `tool_started`
- `tool_completed`
- `context_compacted`
- `agent_completed`

CLI 将事件以简短状态行写到 stderr，最终回答仍写到 stdout。未来可用同一事件接口接入 TUI、WebSocket 或日志系统。

本阶段实现的是 Agent 运行事件流；模型 token 级流式输出留待供应商适配层后续扩展。

## 4. 会话持久化

- `--session ID` 启用会话；ID 仅允许字母、数字、下划线和连字符，最长 64 个字符；
- 文件保存于 `<workspace>/.andi-agent/sessions/<ID>.json`；
- `.andi-agent/` 加入 `.gitignore`，也不出现在 `list_files` 结果中；
- 使用临时文件 + rename 原子保存，降低进程中断导致文件损坏的概率；
- 会话包含完整的模型消息和工具结果，属于可能含敏感信息的本地明文数据，用户应自行保护工作区权限。

## 5. 上下文裁剪

- 配置项 `AGENT_MAX_CONTEXT_CHARS`，默认 120,000 字符；
- system 消息始终保留；
- 其余消息按“从 user 消息开始的一整个交互轮次”分组；
- 从最新轮次向前保留，绝不拆开 assistant tool call 与对应 tool result；
- 若发生裁剪，插入一条系统说明并触发 `context_compacted` 事件；
- 当前轮次即使单独超过预算也完整保留，避免执行中的工具链断裂。

字符预算是简单、可测试的近似值；未来可替换为模型 tokenizer 和模型生成摘要。

## 6. 实施步骤

1. 扩展命令工具，加入可注入的异步审批回调。
2. 为 CLI 实现 TTY 审批器和 `--approval` 参数。
3. 为 Agent 增加结构化事件和带历史运行接口，保持原 `run()` 兼容。
4. 实现按完整轮次裁剪的上下文函数及测试。
5. 实现会话存储、ID 校验和原子保存。
6. 增加 `--session` CLI 装配并更新文档。
7. 完成类型检查、单元测试和 CLI 参数验证。

## 7. 验收标准

- 安全命令不会触发审批；非安全命令只有审批返回 true 才执行；
- 无审批器时非安全命令不会创建进程；
- 测试可观察到稳定、按顺序发出的 Agent 事件；
- 同一 session ID 的后续任务能收到前一轮历史；
- 裁剪后没有以孤立 `tool` 消息开头的历史轮次；
- 会话写入不被 `list_files` 暴露；
- 全部测试和类型检查通过。
